# Initialization handoff

Resolve every field from the final implementation and named evidence. Use `None` rather than omitting a field. Production means deployment of this landing page, never the existing product website or a local URL.

```markdown
## Landing page initialized

- Preview: <exact working local URL>
- Production: <deployed landing-page URL or `Not deployed`>
- App Store source: <canonical URL or `None`>
- Product website source: <canonical URL or `None`>
- Other sources: <user notes, assets, and other first-party URLs or `None`>
- Evidence: <APP_BRIEF.md, app-input/critique.md, and exact research run or artifact paths>

### What the page showcases

- <visible feature or benefit> — <media path> — <final, provisional, or placeholder>

### Assets still needed

- <repo-relative path> — <capture brief> — <current status and reason>
- None

### Completion

- Workflow: collection <status>; copy <status>; build <status>; critique <status>
- Critique: <accepted changes; rejected or deferred findings with reasons; `No valid findings`; or documented fallback result>
- Verification: <commands and desktop/mobile states actually checked>
- Legal: <local routes, source status, and required user/legal review>
- Intentionally omitted: <unsupported content or `None`>
- Publish readiness: <`Ready to deploy` or remaining blockers and nonblocking gaps>
```

List only visibly implemented features. Report every placeholder, provisional image, and missing required image with its exact replacement path and actionable capture brief. Use `None` only when every image is justified final and no required asset is missing.

If desktop or mobile browser QA could not run, publish readiness begins with `Not ready` and names the unverified state.
