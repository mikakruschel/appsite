# Template-fidelity review

Use for pages produced by initialization or the build skill.

- Preserve the starter section order, named components, spacing, typography, responsive behavior, navigation, footer, shared styling, and visual hierarchy.
- A retained composition slot must use its catalog component. Hand-written markup that imitates `ValueCard`, `FeatureCard`, or another available component is a fidelity defect. Shared-component edits must expose reusable behavior rather than hard-code target-app copy.
- A recommendation that violates preservation is `out-of-template-scope`, not an implementable defect. A brief-approved bounded extension remains valid when it carries a core continuity need that existing components could not.
- Unsupported app-specific content may be hidden locally. Its absence does not authorize unrelated recomposition.
- Check navbar CTA compactness, hero slots and crop, feature-card presets, rating decoration, app icon surfaces, and the lack of unrequested platform rows, QR codes, compatibility badges, crop APIs, or extra action visuals.
- For `FeatureCard`, `FeatureIconGrid`, and `ValueCard`, flag a title or label beyond three rendered lines or a description at four or more rendered lines.
- `ReviewsCarousel` keeps its current unique-review count and motion contract. Other explicitly authorized testimonial treatments may use another evidence-backed count.
- Decorative rating laurels frame verified proof and do not claim an award. Their removal is not a default cleanup recommendation.
- A documented placeholder or provisional asset is a handoff unless suitable verified media was ignored or publication with it is in scope.
- Before returning no findings, compare the implemented sequence with the page-composition contract, inspect shared-component diffs, and account for each brief-named core workflow/media mapping and each private starter Blog/Changelog draft.
